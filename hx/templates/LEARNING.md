# 구현 이해와 학습 기록

AI 사용이 허용된 코딩 단계에서 메인이 한국어로 갱신합니다. 아직 구현·선택·검증한 내용은 없습니다. 아래 표는 기록할 항목이며 완료 사실이 아닙니다.

실제 코드 경로·요구사항(R)·결정(D)·질문과 실제 답변(Q)·검증 로그·커밋을 근거로 연결합니다. 제안·예정·미확인과 실제 완료를 구분하고, 수치에는 입력·명령·측정 조건을 적습니다. 사용자와 AI의 판단·수행을 구분합니다. 변경된 선택과 실패도 원인·조치·재검증 근거를 남깁니다.

| 기록할 내용 | 현재 설명 | 근거·확인 상태 |
|---|---|---|
| 해결할 문제와 핵심 개념 | 미작성 | 과제 원문 확인 후 기록 |
| 중요한 기술 용어의 쉬운 뜻 | 미작성 | 실제 사용하는 용어만 |
| 선택한 기술·알고리즘과 이유 | 미결정 | 실제 사용자 결정·코드 연결 |
| 채택하지 않은 주요 대안과 이유 | 미검토 | 비교 조건·장단점 연결 |
| 데이터 구조·DB 테이블·키·처리 흐름 | 미확인 | 실제 스키마·코드 연결. DB가 없으면 해당 없음 |
| 데이터 변환·오류·누락·중복·정합성 처리 | 미확인 | 처리 코드와 검증 연결 |
| 특수 업무 규칙·예외 처리 | 미확인 | 원문·실제 DM·테스트 연결 |
| 발생한 문제와 해결 | 미작성 | 실패·조치·재검증 연결 |
| 테스트·검증 결과와 수치 | 미실행 | 명령·입력·로그·커밋 연결 |
| 실제 사용자 결정·담당자 DM | 아직 기록 없음 | 원문·출처·장부 번호 연결. 모의 답변은 분리 |
| 사용자와 AI가 각각 판단·수행한 일 | 미작성 | 실제 결정과 작업 근거 연결 |
| 개선 내용·남은 한계·향후 개선 | 미확인 | 현재 구현과 미검증 범위 연결 |

## 내 말로 설명해 보기

코딩 단계에서 “어떤 문제를 왜 이 방법으로 해결했는가?”, “입력부터 결과까지 데이터가 어떻게 바뀌는가?”, “어떤 예외를 어떻게 검증했는가?”, “내 판단과 담당자 답변으로 무엇이 바뀌었는가?”를 짧게 설명해 봅니다. 중재는 실제 근거를 대조하고 설명·질문을 돕습니다. 문서 수정은 메인에게 요청합니다.

## 서술형 단계 규정

이전 예선에는 AI 사용·붙여넣기 금지 기록이 있습니다. 실제 본선에서도 적용되면 서술형 단계에서는 AI를 사용하거나 AI 답변을 붙여 넣지 않습니다. 이 기록은 허용된 코딩 단계의 학습 자료이며, 제한 단계에서는 이해한 내용을 바탕으로 직접 작성합니다. 기록 열람 여부도 현장 규정을 따릅니다.
