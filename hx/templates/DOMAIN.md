# 반도체 제조 과제 대응 노트

출제 범위는 공개되지 않았다. 아래 유형은 예상 후보일 뿐이며, 과제 원문이 항상 우선한다.

## 1. 용어 (과제 원문을 읽을 때 필요한 만큼)

| 용어 | 뜻 |
|---|---|
| Fab / 전공정 | 웨이퍼 위에 회로를 만드는 공장·단계. 포토(노광)·식각(Etch)·증착(CVD/PVD)·확산·이온주입·CMP(평탄화)·세정·계측이 수백 step 반복된다(재진입 흐름) |
| 후공정 | 패키징과 테스트. HBM은 칩을 TSV로 수직 적층하는 패키지 제품 |
| Lot / Wafer / Die | Lot은 함께 움직이는 웨이퍼 묶음(보통 25장, FOUP에 담김). Wafer 한 장에 Die(칩) 수백~수천 개. 키 계층은 lot → wafer → die |
| EQP / Chamber / Recipe | 설비 / 설비 안의 공정실(한 설비에 여러 개) / 공정 조건 묶음. 같은 설비라도 chamber·recipe가 다르면 다른 모집단이다 |
| MES | 생산 실행 시스템. lot의 이동 이력(track-in/out), 상태(WAIT·RUN·HOLD), 설비 상태를 기록 |
| FDC | Fault Detection & Classification. 설비 센서 trace(온도·압력·유량·RF 전력 등)를 step별 요약값으로 감시 |
| SPC | 통계적 공정 관리. 관리도에서 중심선 ± 3σ(UCL/LCL)를 벗어나거나 연속 치우침(run rule)을 탐지. 관리 한계(공정의 목소리)와 규격 한계 USL/LSL(고객의 목소리)은 다르다 |
| Cp / Cpk | 공정 능력. Cp=(USL−LSL)/6σ, Cpk=min(USL−μ, μ−LSL)/3σ |
| 계측(Metrology) / VM | 두께·선폭(CD)·overlay 등의 측정 / 센서값으로 계측값을 예측하는 가상 계측 |
| APC / R2R | 계측 결과로 다음 run의 recipe를 보정하는 제어 |
| WAT(PCM, ET) | 공정 완료 후 테스트 패턴의 전기적 특성 측정 |
| EDS (Probe test) | 웨이퍼 상태에서 die별 양/불량 판정. 결과가 bin 코드, 그 분포가 wafer map |
| Yield (수율) | 양품 die ÷ 전체 die. wafer·lot·제품 단위로 집계 |
| Wafer map 패턴 | Center, Donut, Edge-Loc, Edge-Ring, Loc, Scratch, Random, Near-full. 패턴 모양이 원인 공정의 단서 |
| PM / BM | 예방 정비 / 고장 정비. MTBF(고장 간 평균 시간), MTTR(평균 수리 시간) |
| OEE | 설비 종합 효율 = 가동률 × 성능 × 양품률 |
| WIP / TAT | 재공 재고 / lot이 투입부터 완료까지 걸린 시간(cycle time) |
| Q-time | 두 step 사이 허용 최대 대기 시간. 넘기면 재작업 또는 폐기 위험 |
| Dispatching | 설비가 비었을 때 다음 lot을 고르는 규칙. FIFO, EDD(납기 빠른 순), SPT(작업 짧은 순), CR=(납기−현재)/잔여 작업 시간 |
| Hold / Rework / Scrap | 이상으로 정지 / 재작업 / 폐기 |
| Excursion | 공정이 정상 범위를 벗어난 사건. 영향받은 lot 범위를 추적하는 것이 commonality 분석 |

## 2. 어떤 유형이든 공통으로 하는 일

1. **키 정합부터.** lot_id · wafer_id · step · eqp_id · chamber · timestamp로 테이블을 잇는다. `hx profile`의 "Cross-file references"에서 부모 없는 값, 대소문자·공백 차이를 먼저 해결한다. 조인 후 행 수가 늘거나 줄면 이유를 설명할 수 있어야 한다.
2. **시간.** 정렬 여부, 타임존, 형식 혼용, 미래·기본값 날짜, 큰 공백 구간을 확인한다. 이벤트 순서(track-in < track-out)는 `order` 규칙으로 검증한다.
3. **값의 의미.** 단위·스케일 혼용(0–1 대 0–100), -999 같은 센티넬, 0과 결측의 구분, 설비·chamber·recipe별로 다른 정상 범위.
4. **baseline → 개선 → 수치 비교.** 가장 단순한 방법의 점수를 먼저 기록한다.
5. **정답 누수 차단.** 미래 정보로 과거를 예측하지 않는다(시간순 분할). 같은 lot·wafer가 학습과 평가에 나뉘어 들어가지 않게 한다(그룹 분할). 결과를 알고 난 뒤 기록되는 열(판정, 조치 코드)은 입력에서 뺀다.
6. **근거가 있는 결과.** 어느 설비·lot·시점인지, 어떤 값이 어떤 기준을 얼마나 벗어났는지, 무엇을 권하는지. 현업은 점수보다 "왜"와 "그래서 무엇을"을 본다.
7. **사용 가능한 수단.** `hx doctor`가 보여 주는 것 안에서 푼다. ML 프레임워크가 없어도 통계 규칙으로 baseline은 항상 가능하다.

## 3. 유형별 접근

| 유형 | 데이터 모양 | 첫 baseline | 검증 | 흔한 함정 |
|---|---|---|---|---|
| 공정·설비 이상 탐지 | 설비·chamber·recipe별 센서 시계열 또는 run 요약값. 불량 라벨은 드물거나 없음 | 그룹별 robust z-score(중앙값·MAD) 또는 EWMA 관리도, 그다음 Isolation Forest | 라벨이 있으면 precision·recall·PR-AUC(정확도는 불균형에서 무의미). 없으면 주입한 이상을 잡는지, 정상 구간 오탐률 | 설비를 섞어 하나의 분포로 봄. PM 직후·recipe 변경의 수준 이동을 이상으로 오인. 센티넬을 실측으로 취급 |
| 품질·수율 분석 | lot/wafer별 수율·bin, 공정 이력(어느 설비·chamber를 거쳤나), 계측값 | 설비·chamber·recipe·기간별 수율 집계와 차이, 저수율 lot의 공통 경로(commonality) | 표본 수와 함께 제시, 교란(제품·기간) 통제 후에도 차이가 남는지 | 표본 3개짜리 그룹으로 결론. 상관을 원인으로 단정. die 단위와 wafer 단위 수율 혼용 |
| 고장 예측·예방 정비 | 설비 센서 추세, 알람 로그, 정비 이력 | 고장 전 구간의 추세·임계 초과 규칙, 고정 주기 PM과 비교 | 시간순 분할, 고장 몇 시간 전에 잡는지(lead time)와 오경보 수 | 고장 직후 데이터로 학습(누수). 정비 후 리셋을 무시. 고장 건수가 너무 적은데 복잡한 모델 |
| LOT 스케줄링·자원 배분 | lot(제품·step·납기·우선순위), 설비(가능 step·처리 시간·가동 시간), 제약(Q-time·setup·batch) | 디스패칭 규칙(EDD·SPT·CR) greedy, 그다음 국소 탐색 또는 `scipy.optimize.milp` | **출력 스케줄을 `hx check`로 제약 검증**: 설비별 `no_overlap`, lot마다 한 번 `same_keys`, 시작 ≤ 종료 `order`, 자격 설비 `fk`. 목적함수는 하한(설비별 총 작업량 등)과 비교 | 제약 하나를 빠뜨린 "최적해". 시간 단위(분/초) 혼용. 설비 비가동 시간 무시. 무작위 요소로 재현 불가 |
| 제조 로그·이벤트 분석 | 알람·상태 전이·track-in/out 이벤트, 자유 텍스트 메시지 | 이벤트 정규화(코드·설비·시각) 후 빈도·연속 패턴·선후 관계 집계, 상태 전이표로 불가능한 전이 탐지 | 알려진 사건 구간에서 패턴이 실제로 나오는지, 집계 합계가 원본 건수와 맞는지 | 중복 이벤트, 시각 역전, 같은 코드의 표기 변형, 로그 누락 구간을 "이벤트 없음"으로 해석 |
| 데이터 정합성·업무 자동화 | 여러 시스템의 대장(MES·ERP·수기 Excel)과 대조 규칙 | 키 기준 대조와 불일치 유형 분류(누락·중복·값 차이·시점 차이) | `rules.json`으로 규칙을 명문화하고 위반 0건 또는 위반 목록을 산출물로 | 표기 차이를 불일치로 집계. 병합 셀·제목 행이 있는 Excel. 자동 수정이 원본을 덮어씀 |
| 데이터 기반 의사결정 지원 | 위 데이터의 조합과 지표 정의 | 지표 정의를 원문과 대조해 고정, 재계산 가능한 집계와 대시보드 | 지표를 손계산 표본과 대조, 필터 조합의 합계 일치 | 지표 정의가 모호한 채 구현. 화면은 있는데 수치 근거 없음 |

## 4. 결과물 형태를 고를 때

- 원문이 형식을 정하면 그대로 따른다. 정하지 않았다면 "명령 한 줄로 재현되는 스크립트 + 결과 파일 + 짧은 README"가 기본이고, 탐색·조회가 가치의 핵심일 때만 화면을 더한다.
- 화면은 `hx new app` 골격(표준 라이브러리 서버 + 단일 HTML, CDN 없음)에서 시작하면 네트워크와 무관하게 시연된다. 차트는 인라인 SVG나 matplotlib PNG, plotly는 `include_plotlyjs=True`로 내장한다.
