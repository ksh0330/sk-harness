# 운영 세부 참고

빠른 시작은 [README](../README.md), 상황별 지시는 [PLAYBOOK](../PLAYBOOK.md). 아래 명령은 필요할 때 Codex가 실행할 참고용이며 사용자가 외울 필요는 없습니다. `hx`는 설치 출력 또는 과제의 `.hx/GUIDE.md`에 적힌 **Python 명령 + hx 절대 경로**의 줄임말입니다.

## 경로·설치·제출

- `hx init`은 실행한 현재 폴더(또는 하위 명령 앞의 `--root`)에 적용합니다. 과제 의미나 Git 루트를 자동 판별하지 않습니다. 다른 명령은 가까운 상위 `.hx/config.json`을 찾습니다.
- `git clone ...` 후 `python3 sk-harness/hx init`도 과제 루트에서 실행하면 동작하지만 하네스가 과제 안에 생깁니다. `hx snap`의 Git 제외는 전체 폴더 제출 제외를 보장하지 않아 README는 `/tmp/sk-harness`를 권장합니다.
- 기존 AGENTS·스킬은 보존합니다. 충돌 시 첫 프롬프트로 실제 지침을 읽고 누락 절차를 확인합니다. `.hx/GUIDE.md`, DOMAIN, MODEL-POLICY는 재초기화 시 갱신되고 BOARD는 장부에서 재생성됩니다.
- `init --git`은 저장소가 없으면 로컬 Git과 기준 커밋을 만듭니다. 기존 저장소는 현재 HEAD를 `hx-base`로 태그하며 기존 변경을 커밋하지 않습니다. 상위 저장소 안의 하위 폴더에는 새 저장소를 만들지 않습니다.
- `init --deadline HH:MM`은 선택 사항이며 과제에서 확정된 코딩 마감 한국 시각만 사용합니다. 행사 종료 시각(예: 16:00)은 서술형 평가를 포함할 수 있으므로 코딩 마감으로 쓰지 않습니다. 지난 예선 시간표를 재사용하지 않습니다.
- `.gitignore`와 `hx snap`은 전체 폴더 제출 필터가 아닙니다. 과제 안의 `.agents`, `.hx`, `collab`, `.git`까지 현장 제출 방식과 대조합니다. 임의 삭제하지 않습니다.
- ZIP·개인 세션·인증정보는 공개 GitHub에 포함하지 않습니다. 백업 전체 복원은 불필요하며 Git·현재 문서를 우선합니다. 대화에만 있는 중요한 근거가 필요할 때만 사용자에게 백업 확인을 요청합니다.

## 자율 작업과 실제 결정

기본 흐름은 분석 → 담당자 DM → 사용자 결정 → 계획 → 구현 → 검증 → Git → 다음 단계입니다. 일반 조회·분석·코드·테스트는 승인 범위에서 계속합니다. 중요한 해석·알고리즘·스택·아키텍처·범위·방향 변경은 대안과 권장안을 제시하고 사용자 답을 기다립니다. 답변과 무관한 작업은 계속할 수 있습니다.

- 담당자 질문: `hx ask "질문" --to dm --why "목적과 답변별 영향"`. 전송은 사용자.
- 실제 답변: `hx answer Q1 "원문" --source dm`. 가정(`--assume`)은 답변·승인이 아닙니다.
- 선택: `hx decide add`로 대안·권장·근거를 기록하고 `hx brief`로 보여 줍니다. 실제 응답 후 `hx decide set D1 --choice A --note "실제 사용자 원문과 출처"`.
- 수정: `hx feedback add`, 반영·회귀 후 `hx feedback done`.
- 단계: 실제 확인 내용을 `hx phase next --user-said "실제 확인"`에 기록합니다. 프롬프트 시각·모델 권장·모의 응답을 승인으로 만들지 않습니다.

## 기록·검증·Git

- 메인이 `collab/PLAN.md`를 관리합니다. `hx now "현재" --next "다음"`으로 상태를 갱신하고 `hx status`로 확인합니다.
- `init`은 한국어 `collab/LEARNING.md`의 빈 학습 양식을 만들며 기존 파일은 보존합니다. 메인은 단계별 실제 코드·장부·검증·커밋을 연결해 개념·선택 이유·대안·데이터 흐름·예외·문제 해결·사용자/AI 역할·한계를 갱신합니다. 중재는 읽고 설명·검토하며 수정은 메인에게 요청합니다. AI·붙여넣기 제한이 적용되는 서술형 단계에서는 AI 도움을 중단하고 사용자가 직접 작성합니다. 기록 열람도 현장 규정에 따릅니다.
- `collab/BOARD.md`는 자동 생성되므로 직접 고치지 않습니다. 긴 사용자 메모는 `collab/INBOX.md`에 한 사람씩 덧붙입니다. 메인이 `hx inbox`로 읽은 뒤 요구사항·결정에 반영해야 처리 완료입니다.
- `hx run --name unit --req R1 --done -- python3 -m unittest discover -s tests -v`처럼 실제 관련 검사를 연결합니다. 종료 코드·검사 수·실패 이유를 확인합니다. 0개 실행·전부 skip·무관한 통과는 완료 증거가 아닙니다.
- 변경된 증거는 `hx regress --stale`, 통합·최종은 필요한 전체 회귀를 사용합니다. 새 변경·실패·위험 없이 같은 전체 검사를 반복하지 않습니다.
- `hx snap --wip "분석 기록"`은 미완료 체크포인트입니다. `hx snap "검증한 변경"`은 실질적인 PASS 증거가 필요합니다. 둘 다 전체 과제 트리를 stage하므로 무관한 변경이 섞이면 **명시적 파일 경로로 일반 Git 커밋**을 만듭니다. 기존 stage를 흡수하지 않습니다.
- `hx gate --final` 또는 `hx ship`은 최종 회귀를 포함합니다. gate는 등록된 요구사항·증거만 검사하므로 원문 누락·검사 오류·UI·Cofa 제출까지 보증하지 않습니다.
- 복구는 `hx back`으로 계획만 확인합니다. `back --yes`는 작업 트리를 바꾸므로 대상·보존 내용을 확인하고 명시적으로 승인한 경우에만 사용합니다.

## 중재와 훅

중재는 `hx audit`와 실제 소스·Git·테스트 근거를 대조합니다. `hx regress --no-record`도 테스트 자체의 부작용을 막지 않습니다. 명령을 먼저 읽고 안전한 검사 또는 격리 복사본에서만 실행합니다.

검토는 `hx review add` → 메인 `done` → 중재 재검증 후 `close` 또는 `reopen`. high 의견은 handled만으로 종료되지 않습니다. `hx review prompt`는 사용자가 메인에 전달합니다. 명령이 사용자의 역할을 인증하거나 다른 세션을 제어하지는 않습니다.

훅은 선택 사항입니다. 실제 CLI 지원·현장 허용·사용자 선택을 확인한 뒤 `init --hooks`로 파일을 만들고, 제공 `/hooks` 또는 신뢰 UI에서 정의를 검토·승인합니다. 신뢰 우회·전역 설정 변경은 하지 않습니다. 파일 생성, 파싱, 직접 핸들러 실행, 신뢰 후 네이티브 이벤트 실행은 별도 증거입니다. 없어도 상태·결정·검증·Git을 직접 확인하면 됩니다. [공식 훅 안내](https://learn.chatgpt.com/docs/hooks).

스킬은 목록에 보이는 메타데이터와 실제 본문 읽기·절차 수행을 구분합니다. 자동 발견이 안 되면 첫 프롬프트의 파일 경로를 직접 읽습니다. [공식 스킬 안내](https://learn.chatgpt.com/docs/build-skills).

## 모델·규정·연습

본선은 제공 Codex CLI, 메인·중재 Sol 6.1 우선, High 기본입니다. 단순 조회는 Low/Medium, 어려운 최적화·구조 판단·반복 실패는 Extra High를 검토합니다. 실제 허용·제공 목록 우선이며 자동 변경 수단이 없으면 사용자가 제공 화면에서 변경합니다. CLI ID를 추측하거나 현재 세션을 바꿨다고 주장하지 않습니다. 로컬 Astra High 준비와 본선 실행을 구분합니다.

토큰의 평가 반영은 미확인입니다. 정확성과 시간 내 완성을 우선하고 실제 측정이 가능할 때 모델·추론·시간·토큰·결과를 기록합니다. 미측정을 절약률로 만들지 않습니다. 인터넷·패키지·개인 키를 기본 전제로 삼지 않습니다. `doctor --net`은 외부 DNS/TCP 접속이므로 별도 허용 없이는 사용하지 않습니다. 자세한 근거와 서술형 AI·붙여넣기 제한은 [규정 문서](COFA-RULES.md)를 따릅니다.

메인과 중재는 사용자가 각각 실행하는 별도 세션입니다. 대화·컨텍스트·사용량을 자동 공유하지 않습니다. 인수 시 BOARD·PLAN·LEARNING과 관련 장부·최근 Git만 먼저 확인하고, 같은 파일 전체를 반복해서 읽지 않습니다. `/model`·`/status`가 실제 제공되면 선택과 상태를 확인하되 Cofa의 추론 수준 조절 지원은 현장에서 확인합니다. [공식 CLI 안내](https://learn.chatgpt.com/docs/developer-commands?surface=cli)는 일반 기능의 근거이며 Cofa 지원을 입증하지 않습니다.

연습은 `practice/tasks`의 문제만 별도 폴더에 복사합니다. `practice/reference`는 평가자만 읽으며 질문 전 답을 풀이 세션에 노출하지 않습니다. 준비 감사는 `.audit-work/rehearsal`과 분리합니다. 명령 시뮬레이션·로컬 Codex 동작·실제 사람 응답·Cofa 동작을 각각 보고합니다.

유지보수 테스트는 준비 저장소에서 `python -B -m unittest discover -s tests -v`로 실행합니다. 본선 시작 때 전체 하네스 테스트는 필요하지 않습니다. `D:/ex-harness`는 읽기 전용 참고이며 설치·검사·수정 대상이 아닙니다.
