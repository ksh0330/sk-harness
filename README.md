# 본선 시작

**Cofa 터미널에서 처음 열린 현재 폴더가 기본 작업 공간입니다.** 과제 원문·데이터·기존 소스가 있는지 `pwd`, `ls -la`로 확인하세요. Git이 있으면 `git status --short`와 `git rev-parse --show-toplevel`도 확인합니다. 별도 task-folder는 만들지 않습니다.

## 1. 터미널에 복사

현재 폴더에서 아래 두 줄을 한 번에 실행하세요. 공개 Clone·사전 코드·Python 실행은 현장 규정을 따릅니다.

```bash
git clone https://github.com/ksh0330/sk-harness.git /tmp/sk-harness &&
python3 /tmp/sk-harness/hx init
```

## 2. 정상 적용 확인

화면에 **`hx initialised in ...`**과 **`shared state: collab/BOARD.md`**가 나오고, 표시된 경로가 현재 과제 폴더면 초기화가 완료된 것입니다. `kept existing ... (differs, not modified)`는 기존 지침이나 파일을 보존했다는 뜻입니다. 메인 첫 프롬프트가 기존 지침과 hx 절차를 함께 확인합니다.

메인·중재·설계·검증 스킬, hx 실행 경로 안내, 요구사항·결정 기록 체계와 공유 문서가 준비됩니다. 훅은 기본으로 켜지지 않습니다. Git 체크포인트는 메인이 기존 변경을 확인한 뒤 만듭니다. **파일 준비와 AI의 실제 지침 적용은 구분**하며, 다음 프롬프트로 실제 적용을 확인합니다.

## 3. Codex 실행

같은 터미널·과제 폴더에서 실행합니다.

```bash
codex
```

제공 모델 선택 화면에서 **Sol 6.1 / High**를 우선 선택하세요. `/model`을 제공하면 모델·추론 수준을 확인하고 `/status`로 현재 설정을 확인합니다. 실제 Cofa 목록과 규정이 우선이며, 없다고 도구를 업데이트하거나 설정을 우회하지 않습니다.

## 4. 메인 세션 첫 프롬프트

```text
메인 세션으로 시작해. 현재 폴더가 과제 원문·자료가 있는 작업 공간인지 Git 상태·루트와 함께 확인해.

--version, doctor(네트워크 제외), status, req list와 공유 문서를 확인해. 충돌·실패는 숨기지 마.
현장 확정 정보: 참가번호 141번으로 홀수 과제인 '기업 간 거래관계 및 기업정보 분석 Agent 서비스 구현' 대상이다.
짝수 과제인 'Overlay 불량 원인 장비 분석 서비스 구현'으로 진행하지 마.
현업 담당자의 실제 고민을 해결하는 서비스가 목표이며 기능과 사용자 중심 UI/UX를 함께 구현·검증해.
문제 풀이 결과와 발표용 HTML은 15:00, 서술형은 15:30 마감이다(한국 시각).
GUIDE의 실제 hx 명령으로 init --deadline 15:00을 적용하고, 현재 시각·남은 시간에 맞춰
핵심 업무 흐름 구현·검증과 두 제출물 준비·제출 확인 시간을 PLAN에 확보해. 15:30을 코딩 마감으로 쓰지 마.

발표용 HTML은 실제 구현·실행·검증 근거로 간결하게 작성하고 미구현·미검증·한계를 구분해.
별도 발표 자료 확장 때문에 서비스 구현·핵심 검증이나 15:00 제출이 늦어지지 않게 해.
Top 20 선정 후 1인당 10분 Progress Review, Top 6 선정 후 1인당 5분 무대 피칭에 대비하되
검증된 서비스·발표용 HTML·LEARNING을 재사용해. 새로운 필수 산출물로 확대하지 마.
담당자 DM은 내가 보낼 문장으로 만들어. 중요한 해석·알고리즘·스택·구조·범위는

첫 점검 결과와 체크포인트 해시 또는 실패 이유, 지금 내 결정이 필요한 항목을 알려줘.
```

## 5. 중재는 필요할 때 별도로 실행

분석·설계의 중요한 선택 전, 구현 중 점검이 필요할 때, 최종 검증 전에 여세요. 사용자가 **두 번째 터미널 또는 Cofa가 허용하는 새 세션**을 열고, 1번에서 확인한 **같은 작업 공간**에서 `codex`를 실행합니다. 초기화 명령은 다시 실행하지 않습니다. Sol 6.1 / High를 우선 선택하고 아래 프롬프트를 붙여 넣으세요.

```text
중재 세션으로 시작해. 적용되는 AGENTS.md와 .agents/skills/hx-mediator/SKILL.md,
.hx/GUIDE.md를 읽고 실제 스킬 인식·본문 읽기 여부를 구분해 알려줘.
hx status·audit, 과제 원문, BOARD·PLAN·LEARNING, 요구사항·결정·실제 DM,
코드·테스트·검증 근거·Git 상태·diff·이력을 대조해. 확인한 진행 상태와 누락·오류를 설명해.
GUIDE의 현장 확정 정보(141번 홀수 과제, 결과·발표용 HTML 15:00, 서술형 15:30)를 기준으로
기능·핵심 사용 흐름과 정보 탐색 편의성·Agent 분석 근거와 설명·제출물을 독립 검토해.
후보 기능을 필수로 오해했는지, 화면·Agent 결과와 원본 데이터·처리 근거가 일치하는지,
발표용 HTML의 주장·수치가 실제 구현·검증과 일치하는지 확인해. 미확인 UI는 통과로 보고하지 마.
Top 20의 10분 Progress Review와 Top 6의 5분 피칭 대비가 구현·15:00 제출을 지연시키는지도 확인해.
알고리즘·기술 선택의 근거와 내게 필요한 결정을 알려주고 메인에 붙일 짧은 수정 프롬프트를 만들어.
LEARNING을 근거로 용어와 구현을 쉽게 설명하고, 요청하면 짧은 이해도 질문을 해줘.
코드·계획·학습 문서·Git·설정은 수정하지 마. 검토 기록만 hx review로 남기는 것을 허용한다.
재검사는 명령을 먼저 확인하고 격리 환경이나 안전한 검사만 사용해. 메인을 직접 제어한다고 가정하지 마.
```

두 AI는 **대화·컨텍스트·사용량을 자동 공유하지 않습니다.** 공유 Markdown·실제 파일·Git으로 확인하며, 중재의 수정 요청은 사용자가 메인에 복사해 전달합니다.

## 6. 설정에 실패하면

오류 메시지를 복사해 제공 Codex에 아래 공통 복구 프롬프트를 전달하세요. 아래 표의 짧은 문장도 함께 붙이면 됩니다.

```text
현재 설정 오류를 분석해. 기존 과제 파일과 지침을 보존하고, 설치된 도구와 실제 경로를 확인한 뒤
안전한 방법으로 수정해. 필요한 경우 hx 없이 직접 지침을 적용하는 방법을 제안해.
전역 설정이나 제공 도구를 업데이트하지 마. 현장 규정을 위반하는 설치·우회는 하지 마.
[오류 메시지와 아래 표의 해당 문장 붙여 넣기]
```

| 상황 | 내가 확인할 것 | Codex에 덧붙일 문장 |
|---|---|---|
| Git Clone 실패 | 오류 원문·현장 Clone 허용 | 저장소 주소와 연결·권한을 확인해. 불허면 직접 지침으로 진행해. |
| `/tmp/sk-harness`가 이미 있음 | 기존 폴더 출처 | 지우거나 덮어쓰지 말고 출처·버전을 확인해. 필요하면 과제 밖 다른 경로를 제안해. |
| `python3` 실행 불가 | `python --version` | 설치된 Python 3.10 이상이 있으면 그 실행 경로를 써. 없으면 무설치 방식으로 진행해. |
| `hx init` 실패 | 오류 원문·표시된 경로 | 실패 원인과 생성된 파일을 확인하고 기존 파일을 보존하며 복구해. |
| 기존 AGENTS와 충돌 | `kept existing` 표시 | 기존 AGENTS와 hx 스킬·GUIDE를 함께 읽고 충돌을 설명해. 중대한 충돌은 내게 물어봐. |
| 스킬 인식 안 됨 | 같은 과제 폴더에서 실행했는지 | 실제 스킬 경로를 확인하고 본문을 직접 읽어 적용해. 필요하면 같은 폴더에서 새 세션을 안내해. |
| hx 명령 사용 불가 | Clone 폴더가 남아 있는지 | `.hx/GUIDE.md`의 Python·hx 절대 경로를 확인해. 불가능하면 Markdown·직접 Git으로 이어가. |
| 훅 사용 불가 | 기본 실행에 불필요 | 훅 없이 상태·질문·검증·Git을 직접 확인해. 신뢰 승인을 우회하지 마. |
| Git 초기화·커밋 실패 | 오류·기존 stage·상위 Git 루트 | 기존 stage·변경을 보존하고 원인을 알려줘. 식별자 미설정이면 git config를 바꾸지 말고 `hx / hx@localhost` 임시 식별자로 커밋해. 안전한 로컬 체크포인트가 안 되면 문서로 상태를 남겨. |
| 커밋 때 권한 승인 창이 뜸 | Codex 승인 요청 내용이 `git add/commit`인지 | 정상 승인 절차로 커밋해. 승인할 수 없으면 우회하지 말고 커밋 못 한 파일과 이유를 PLAN에 남겨. |
| `source_changed_during_run` | 출력에 표시된 파일이 결과 파일인지 | `--watch`를 실제 입력·코드로만 좁혀 다시 실행해. `data/*`처럼 결과까지 포함하는 패턴은 쓰지 마. |
| 이름·이메일 등 실제 정보 요구 | 공식 제출용인지 테스트용인지 | 임의로 채우지 말고 필요한 값과 위치를 나에게 물어봐. 테스트는 가짜 값을 쓰고 실제 값은 커밋하지 마. |
| 작업 경로를 잘못 선택 | `pwd`와 원문·자료 위치 | 잘못 생성된 파일을 임의 삭제·이동하지 마. 실제 과제 경로를 확인해 거기서 적용하고 잔여물을 알려줘. |

## 진행과 서술형 대비

메인은 **원문·자료 분석 → 담당자 질문 → 사용자 판단 → 기술·알고리즘 비교 → 계획·초기 Git → 구현·테스트·수정 → 단계별 커밋·기록 → 최종 검증·설명**을 주도합니다. 중요한 선택은 사용자가 하고, 단순 조회·안전한 실행·테스트·사소한 수정은 AI가 계속합니다.

코딩 중 메인이 `collab/LEARNING.md`를 한국어로 갱신합니다. 사용자는 “이번 구현을 쉽게 설명해 줘”라고 요청하고 중재에게 근거 확인과 짧은 이해도 점검을 받을 수 있습니다. **본선 서술형에서 AI·붙여넣기 금지가 적용되면 그 단계에서는 AI를 사용하거나 AI 답변을 붙여 넣지 않습니다.** 기록은 AI 사용이 허용된 코딩 단계에서 준비하며, 제한 단계에서는 사용자가 이해한 내용으로 직접 작성합니다. 기록 열람 허용도 현장 안내를 따릅니다.

## 기본 환경이 다를 때만

- **현재 폴더에 과제 자료가 없으면:** 실제 자료가 있는 폴더로 이동한 뒤 적용하세요. `/tmp/sk-harness`는 도구 보관 장소이므로 그 안으로 `cd`하지 않습니다. 도구는 과제·제출 폴더 밖에 두고 작업 중 옮기지 않습니다. `/tmp`는 재시작 시 사라질 수 있습니다.
- **다른 위치에서 초기화해야 하면:** `python3 /tmp/sk-harness/hx --root "/실제/과제/경로" init`. Codex는 실제 과제 폴더에서 실행합니다.
- **Windows PowerShell이면:** 과제 루트에서 `git clone https://github.com/ksh0330/sk-harness.git "$env:TEMP/sk-harness"` 후 `python "$env:TEMP/sk-harness/hx" init`. TEMP도 과제 밖인지 확인합니다.
- **Clone·Python이 불허되면:** 제공 Codex에 “원문·지침·Git부터 확인하고 요구사항·내 결정·실제 DM·검증·계획·학습 내용을 한국어 공유 Markdown에 기록해. 중요한 선택은 내 답을 기다리고, 승인 범위에서 구현·테스트·로컬 Git을 진행해. 별도 중재는 읽고 수정 요청만 전달해. 현장 규정을 지키고 도구 업데이트·전역 설정 변경·외부 전송은 하지 마.”라고 요청하세요.

진행 중 복사할 문장은 [PLAYBOOK](PLAYBOOK.md), 세부 명령·훅·시간 관리는 [고급 참고](docs/OPERATIONS-REFERENCE.md), 규정 근거는 [COFA-RULES](docs/COFA-RULES.md), 최근 검증은 [검증 기록](docs/evidence/cofa-final-2026-11-11.md)과 [hx run 보완 기록](docs/evidence/hx-run-watch-2026-11-11.md)을 확인하세요.
